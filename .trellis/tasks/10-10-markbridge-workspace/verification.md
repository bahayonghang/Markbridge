# 验证矩阵与证据格式

## 当前状态

本文是待实现后的验收合同。下列所有产品检查当前均为 NOT_RUN。规划阶段只验证文档和任务结构。

## 数据和环境

- 原生主环境：Windows 11 x64、记录的 Chrome 稳定版（最低 134）、WebView2 版本、CPU/RAM/磁盘、构建 hash。首次验收记录实际版本。
- B100：100 条书签、嵌套文件夹、重复 URL、中文/英文、特殊分隔符与需保护节点的合成树。
- B10K：10,000 条书签，最大深度 20，1,000 个文件夹，重复 URL 和相同标题。测试生成器使用固定 seed=20261010。
- P2：两个一次性 Chrome Profile，刻意出现相同 chromeId。禁止将正常用户 Profile 当作默认测试环境。
- HTTP fixture：静态 HTML、动态页、CSP 限制、登录页、坏编码、重定向、私网目标、大响应、慢响应和恶意脚本。测试服务仅在隔离 harness 显式允许，生产公共 fetch 策略不能因此放宽。
- AI fixture：确定性模拟响应，加一个用户明确配置的本地 Ollama 模型实测；云端实测仅在用户授权账号/成本后执行。

## 门槛

| Gate | 内容与样本 | 通过条件 | 所属 |
|---|---|---|---|
| V01 | 基础 lint/typecheck/test/build、Rust gates、协议生成 | 命令退出 0；锁文件可重建；没有未解释警告 | 01、02、所有受影响任务 |
| V02 | P2 配对、错误令牌/Origin/Profile、吊销 | 未授权消息零缓存写入和零浏览器写入；等 ID 不串资料 | 02、03 |
| V03 | 在线 B10K，Chrome 新增/修改/移动/删除各 25 次 | 100 次变化从 Chrome 事件到 UI 可见均 <=3 s；记录 p50/p95/max；最终树等价 | 03、05 |
| V04 | worker 重启、Chrome 重启、丢事件、导入、休眠恢复 | 明确 reconciling；静止树下 full refresh 后一致；写入只在校验完成后恢复；显式重连在本机正常调度下 <=10 s | 03、04 |
| V05 | 文件原子替换、半写 JSON、删除/重建、路径不可访问 | 保留最后有效树并显示 stale；恢复有效数据后更新；Chrome 文件写入次数为 0 | 04 |
| V06 | B10K 搜索 30 次（冷热各记录） | 暖态输入后 p95 <=200 ms 返回可交互结果；进程启动到可操作缓存树 <=3 s（3 次冷启动分别记录） | 05、13 |
| V07 | 每种 CRUD、排序、根/managed、并发改动 | Chrome 与缓存一致；受保护变更拒绝；外部修改冲突明确；无静默覆盖 | 06 |
| V08 | ack 丢失、apply 后 crash、删除恢复、rollback 并发 | 不重复 create/delete；不确定状态保留；无冲突时语义树+顺序+元数据恢复；有冲突不覆盖外部值 | 06、11 |
| V09 | 标签本地模式与标题模式、竖线/反斜线、外部改名 | 本地模式 Chrome 标题完全不变；编码只作用选中范围且可逆；不重复追加；标签迁移可回退 | 07 |
| V10 | 快速 A/B 切换 20 次、离线缓存、HTTP fixture | 旧请求不覆盖当前选中；10 s 超时可见；受禁目标/重定向失败；图片路径同样受限 | 08 |
| V11 | 原生网页、独立登录、恶意页面调用每个敏感 command | main 和 preview 会话隔离；无 IPC/密钥/文件权限；危险 scheme、弹窗、下载按设计处理；有原生截图与拒绝回执 | 09 |
| V12 | 模拟好/坏 schema、超长值、注入文本、取消、429；10 页本地模型 | 确认前零书签写入；取消无晚到应用；每条建议可编辑；10 页均给出可追溯建议或明确失败，无伪造成功 | 10 |
| V13 | B100 两遍分类、拒绝部分项、应用第 40 步断连/重启 | 每条恰好一个处理结果；恢复定位已执行范围；条件回滚恢复语义树和顺序；无额外删除 | 11 |
| V14 | 404/410、403/429、timeout、带不同 query/fragment 的 URL | 未知状态不报死链；不同资源不误合并；清理前预览和确认；可撤销 | 12 |
| V15 | 构建后隔离目录安装、启动、配对、退出、重启、卸载 | 包内资产齐全；实际安装程序可启动；数据保留策略符合说明；无未知 listener 残留 | 13 |
| V16 | 专用 Floccus 测试库与第二设备/客户端 | 标题/移动传播有人工证据；侧车不会被描述为已同步；无环境则 UNVERIFIED | 13 |
| V17 | macOS/Linux 分别运行 V02/V04/V08/V11/V15 | 原生平台逐项通过，不能用 Windows 或交叉编译代替 | 14 |
| V18 | 10,000 本地向量、20 条标注查询、模型切换 | 固定模型/维度下 Recall@5 >=0.8；暖态 p95 <=1 s；取消可恢复；关闭后普通搜索可用 | 15 |

V03 的 3 秒只衡量 live 期间。V04 的后台 alarm 自动重连受 Chrome/OS 调度影响，只记录恢复耗时，不将最小 alarm 周期误写成固定 SLA。V06 是拟定本地验收目标；首次实测需保留机器参数，不凭此声明所有硬件性能。

## 记录要求

每个子任务创建 evidence/receipts.md：日期、平台、代码版本/未提交差异摘要、命令、退出码、fixture、原始单位、结果、失败原因、重测关联与原生截图路径。不将 URL token、密钥、真实书签正文写入收据。

状态仅用 PASS、FAIL、NOT_RUN、UNVERIFIED。M4 未满足核心 V01–V15 时不能称 Windows 验收完成。V16 依赖外部测试环境，可明确作为兼容性未验证项保留，不虚构跨设备结果。M5 缺失环境时任务保持未完成。
