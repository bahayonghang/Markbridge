# 技术与交互设计

## 信息架构

四个工作区：书签、整理、操作历史、设置。设置分 Chrome 连接、AI、备份导出。首次无来源时主区显示接入引导，AI 不进入首次流程。已接入直接进入上次有效目录，详情按需显示。

```text
原生 Windows 标题栏
┌──────────────┬──────────────────────────────────┐
│ Markbridge   │ 面包屑                来源状态    │
│ Chrome 资料  │ 搜索                    新建      │
│ 全部书签     ├────────────────────┬─────────────┤
│ 文件夹树     │ 书签列表           │ 按需详情    │
│ 本地标签     │ 标题 / 站点 / 标签 │ 标签备注    │
│              │ 多选替换工具条     │ 内容预览    │
│ 整理         │                    │             │

│ 设置         │ 数量 / 当前状态                  │
```

CSS 策略：沿用普通 CSS，语义变量与组件作用域类名；不混 Tailwind/CSS-in-JS。视觉以 visual-design.md 为准。

## 所有权

App 负责导航、统一提示和唯一 useBridge 订阅；LibraryWorkspace 保持 source/folder/query/filter/selection 的 UI 状态，不能出现两份可独立修改的树。backend.ts 继续校验 DTO。Rust 唯一写 SQLite，扩展唯一写 Chrome。

ConnectionSettings/Onboarding 共用既有配对状态机；编辑表单与 diff 分离，HistoryWorkspace 独立挂载；详情/整理复用现有 feature 模块。草稿以来源、profileId、sourceEpoch、节点身份、基准 revision 绑定，旧异步响应按请求代次丢弃。换源清选择和未确认预览；未保存输入需明确保留/放弃，不静默覆盖。

## 浏览搜索与选择

默认按 Chrome 顺序展示。路径不是身份。查询合同表达 source、folderScope（全部/当前目录及后代）、query、tagIds；标签和文本取交集。标题/URL 默认搜索，本地摘要/备注为明确可选范围。独立文件镜像只搜索已有标题/URL，不伪造侧车能力。

R03 扩展本地查询 DTO：offset/limit/expectedRevision 输入，revision、total 或 hasMore、下一页位置输出。稳定排序含第二键；revision 变化重置分页，避免重漏。200 是每页限制而非总结果上限。缓存分页不增加 Chrome wire 命令。mirror 采用同一可达语义，容器驱动虚拟列表，不能一次渲染 10000 行。

单击选中、双击/Enter 打开或进入；Ctrl 切换选择，Shift 连续选择，Ctrl+A 只选明确标识的已加载结果，不暗选未加载匹配。目录/查询/筛选/来源变化清多选并提示；外部删除剔除失效项。确认前后端再次校验范围。父子同选由后端去重，影响计数包括实际子树。

## 编辑与批量

新建只依赖可写目标目录；书签/文件夹独立表单。保存展示字段 diff 并确认。移动目标树可检索完整路径，禁用自身/后代/保护目录；拖放与快捷键仅生成待审查动作。

普通批量移动/删除由 Rust 计划，不在 React 循环 applyEdit。R04 扩展原 edit/operations 的操作分组，复用串行 executor、保护校验、快照、HTML/sidecar 备份和 receipt。计划绑定 profileId/sourceEpoch/baseRevision/去重集合/目标与顺序/before-state/数量/确认摘要；apply 引用已审查标识，不能临时换列表。

整个批次备份成功才执行第一步；Profile 串行，内部 revision 推进与外部 before-state 冲突区分。逐项记录已执行/未执行/冲突/不确定。断线或不确定停止，禁止非幂等自动重试。取消只停止剩余项；大范围删除沿用既有二次确认门槛。批量本地标签走本地事务，可选标题编码另行审查。

新增 DTO 同步 crates/protocol、packages/protocol；必要操作分组 migration 在 R04 内带升级备份完成，不另建通用任务框架。

R04复用既有operations JSON扩展批次元数据，没有新迁移。单条/批量移动删除在wire中可携带`expectedSubtree`，扩展在实际写入前比较完整审查子树。旧记录缺此字段仍可读；旧版严格校验扩展会拒绝新字段，因此R08交付指南必须要求桌面与扩展配套更新，不能把单独替换桌面描述为兼容升级。单次日常删除的去重完整子树最多1000项；所有正向步骤和已知逆向消息都在首次写入前校验16MiB帧限额，超限拒绝而不自动拆批。

## 详情和整理

详情为信息、标签备注、内容预览分区；ID/版本进诊断折叠。预览遵守现有去抖/取消，不默认全库抓取或请求第三方 favicon。完整网页仍使用 preview-* 独立窗口，不在可信 DOM 嵌远程 HTML/iframe。

整理接收显式范围，进入不自动检查。AI 未启用不影响普通管理，配置移入设置；生成前展示端点/数据范围，应用需独立确认。任务返回书签后仍可查结果，未确认草稿不得被应用。

## 历史、导出、撤销

历史按 Profile 显示时间/类型/数量/真实状态，详情有前后值与冲突。非 live 可查看和导出缓存，撤销需要 live。「已核对」不是自动成功。

HTML/sidecar 导出通过受限原生保存对话框和 Rust 落盘，结果区分 saved/cancelled/failed。只授权用户所选位置，取消不报成功。输出绑定一致缓存 revision，并标来源时间。独立镜像可导 HTML，没有侧车不虚构 JSON。导出不等于任意全库恢复。

撤销按原 undo 条件恢复语义树/兄弟顺序/侧车，不覆盖外部新值；删除恢复 ID 映射后端负责。批次按已执行子操作逆序逐步条件检查。

## 兼容与回退

保留数据目录、扩展权限与安全检查。R01 不改 DB/DTO；其余按责任同步生成。高版本 migration 不能靠旧代码强读；有未完成操作保留回执不重放。代码回退不等于浏览器数据恢复。旧命令/门槛真正变更时同步旧父子计划，不改写历史收据。旧门槛详见 task-map.md。
