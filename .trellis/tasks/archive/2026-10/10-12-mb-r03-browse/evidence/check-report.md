## Findings (fixed)

- File: `apps/desktop/src/features/ai/AiSuggest.tsx`, `features/tags/TagDesk.tsx`, `features/library/LibraryWorkspace.tsx`.
  Issue: a confirmed AI local summary/tag save does not advance the Chrome revision, so the active query retained its old page/offset and AI-created tags were absent from both filter and detail catalogs. A pending tag/note save also captured the old filter callback. A selection change during confirmed AI apply discarded the metadata invalidation together with stale presentation state.
  Fix: confirmed `tagsApplied`/`summaryApplied` triggers the latest callback before the stale-selection presentation guard. The workspace verifies the source and source-visit generation, restarts sidecar-dependent queries, and increments `TagDesk.refreshVersion`. The existing cancellable catalog effect then refreshes the current selection and publishes its catalog to the parent without remounting the detail editor. TagDesk uses its latest change callback when a pending command completes.
  Regressions: a 201-result summary query becomes 200 after a local save without a Chrome revision change; both tag selectors immediately contain the new AI tag; a note filter activated during a pending save is invalidated; changing the active bookmark during confirmed AI apply still invalidates saved metadata without displaying the previous item's success state.
  Evidence: `check-regression-reproduced.log`, `check-ai-catalog-first.log`, `check-ai-selection-race-first.log` preserve the failures. `check-affected-tests-receipt-final.log` passes all affected tests.

- File: `apps/desktop/src/features/library/LibraryWorkspace.tsx`.
  Issue: mirror refresh retained a deleted current folder and active bookmark, leaving an empty list even when another valid root/directory existed.
  Fix: validate the current mirror folder against the new snapshot, fall back to a valid root, prune deleted selection IDs, and remove a deleted active item while preserving the existing rootless-bookmark fallback.
  Regression: remove the currently open mirror folder and its selected bookmark; the surviving root is selected and its children remain reachable.
  Evidence: `check-regression-reproduced.log` fails before the fix; `check-review-fixes-retest.log` and the final affected suite pass. The earlier `check-regression-first.log` also records an invalid test fixture with extra mirror DTO fields; the corrected fixture reproduced the actual product defect before editing the product.

- File: `apps/desktop/src/features/library/VirtualRows.tsx`, `LibraryWorkspace.tsx`.
  Issue: after reaching the 10001st mirror row, entering a search reduced the loaded page to 200 but retained the old scroll offset. The previous active item was absent, so the scrolling effect returned early. The first result was unreachable through the expected initial keyboard focus, and `aria-activedescendant` referred to an unmounted row. The main thread independently reproduced the same failure in native WebView2.
  Fix: pass the selection/query identity as `resetKey`, reset scrolling when there is no valid active item, and emit `aria-activedescendant` only for a mounted active row. Ordinary scroll and next-page loads under the same query keep their position.
  Regression: mirror list 10001st row → new search → first result visible at scrollTop 0; another query with activeIndex still -1 also resets; normal scrolling and loading the next page retain scrollTop 5200.
  Evidence: `check-mirror-scroll-first.log` fails before the fix; `check-mirror-scroll-retest.log` and final affected tests pass. Native final-build verification remains main-owned.

- File: `apps/desktop/src/features/library/LibraryWorkspace.tsx`.
  Issue: duplicate cleanup and undo can write local metadata only after an operation receipt. The Chrome event may already have advanced the profile revision and triggered a query before `bridge/edit.rs` copies restored metadata or applies/reverses tag merges. The subsequent receipt publication advances the global BridgeState revision, while the profile revision stays unchanged, leaving the query stale.
  Fix: after main approved the notification boundary, add the existing global BridgeState revision to query and selection identity only when tags or optional summary/note text affect the result. This is conservative invalidation, not a precise metadata event: an unrelated profile publication can also reset the current sidecar query. No subscription or DTO was added. Ordinary title/URL queries do not depend on this token, and TagDesk's catalog/draft effect is not keyed by it.
  Regression: Chrome profile revision changes first; a later receipt changes only the global revision and local match set; the stale selection clears and results reload. An unsaved note remains intact, and a later global-only publication does not issue another ordinary title query.
  Evidence: `check-receipt-metadata-first.log` fails before the fix, `check-receipt-metadata-retest.log` passes. OrganizationDesk's current `plan_reclassify` path only creates/moves folders/bookmarks; preview/link caches do not write the searched bookmark metadata.

The implementation agent separately corrected the deep-path breadcrumb scroll and tree sibling ARIA positions before the review handoff. Those fixes were included in the independently rerun browser suite.
