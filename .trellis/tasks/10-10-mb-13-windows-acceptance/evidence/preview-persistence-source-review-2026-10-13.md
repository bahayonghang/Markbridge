## Source review

- `PreviewHost::open_page` derives a per-profile directory and passes it explicitly to `WebviewWindowBuilder::data_directory`; A uses the same derivation on reopen. A profile change destroys the previous preview. Ordinary close does not call `clear_session` or remove its files.
- Before the fix, `session_directory` hex-encoded every byte of the validated profile id. A production `p:` plus 64 hexadecimal characters became a 132-character directory component. The short synthetic probe identity became 32 characters. This is a concrete multiplier, not an observed Windows error code.
- `destroy_preview` waits for the Tauri window to disappear, rather than the browser process. The formal A process was nevertheless already absent when B was open and before A reopened, weakening an immediate browser-process race as the explanation.
- The locked Wry 0.57.0 controller closes on drop, and its Windows context does not retain a separate native environment after the last view. Incognito is not enabled in the product builder and defaults false in the inspected SDK. Native Profile properties have not been measured.
- [Microsoft Environment5](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2environment5?view=webview2-1.0.3967.48) requires retaining the environment until BrowserProcessExited can be delivered. An event observer therefore changes the suspect lifetime and must not be mistaken for an uninstrumented fix.
- [Chromium LocalStorageImpl](https://chromium.googlesource.com/chromium/src/+/00549647c677fa9bab69f9d6edcf070c257cbcda/components/services/storage/dom_storage/local_storage_impl.cc) opens a disk-backed LevelDB, and its database-open failure path retries then falls back to memory. This supports the possibility of a same-window success with failed persistence; it is not evidence that the installed runtime reached that branch.

## Approved focused fix and source verification

The same-executable length pair and the actual path derivation identify the full-id directory expansion as the product trigger. The formal A retained data-directory candidate measured 279 UTF-16 units including NUL for `Default/Local Storage/leveldb/MANIFEST-000001`; it exceeds the [documented Windows MAX_PATH family](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation). We did not capture a native database-open error code and do not claim a specific Chromium fallback branch was observed.

The approved directory component is exactly `v1-` plus lowercase full SHA256 of `markbridge:preview-session:v1`, one NUL byte, then validated Profile id UTF-8 bytes. The fixed 67-character component is disjoint from legacy hexadecimal names. `p:` plus 64 `a` characters pins to `v1-1e8b1719ad8820ff052aad43fffc0161b789f8e67db43ed3d05c94dd40b345f7`. Protocol ids and per-profile isolation are unchanged.

After closing the previous preview under the existing operation lock, the code checks the exact owned root and derived source/target directories. An existing legacy directory migrates only to an absent target; directory links/reparse points and links anywhere in its tree are refused. Canonical source and target parent must match. Windows uses extended absolute paths and `MoveFileW`, which refuses an existing destination, so no merge/overwrite occurs even if a destination appears after the initial check. Both-present conflicts return StorageError and preserve both. Legacy components over the supported 255-character limit cannot have been created by the old Windows mapping and are excluded explicitly, so valid maximum-length protocol ids can use the new path; unrelated metadata errors are not converted to absence.

Potentially large preparation/migration metadata walks and each clear attempt run through Tauri's blocking pool with owned root/profile/path values. The existing asynchronous preview operation lock still serializes them. Join failure returns a stable StorageError or refuses removal; no filesystem exception text enters IPC.

Only the Windows preview candidate is subject to the known persistent-store budget: `EBWebView/Default/Local Storage/leveldb/MANIFEST-000001` plus NUL must fit 260 UTF-16 units. Rejection occurs before candidate creation or WebView construction. `PreviewHost::new` still accepts a long ordinary app-data root, allowing unrelated application use; it validates root ancestors before creating the dedicated preview root. This guard addresses the measured storage-path family, not all future Chromium filenames. Explicit user-triggered session clear removes only that profile's hash and supported legacy directories, with the same ownership/link refusal.

Non-Windows fresh hashed paths are implemented, but legacy migration currently fails closed pending task14's atomic no-replace platform primitive. No macOS/Linux migration or native support claim is made.
