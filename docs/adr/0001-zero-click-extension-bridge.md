# ADR-0001: 采用固定扩展 ID 与自动本地端口探测替代人工配对码

原有连接流程要求用户在桌面端手动启动本地监听、填写资料名称并生成 120 秒过期的一次性 JSON 配对串、切换 Chrome 打开扩展选项页粘贴后再切回桌面核对扩展 ID 与 Origin 确认，六步跨窗仪式严重阻碍首次上手与日常重连。我们决定在扩展清单中写入公开 RSA 公钥以锁定全球唯一的 32 位 Chrome 扩展 ID（私钥不入库），桌面端启动即自动绑定 `127.0.0.1:49153–49160` 首个空闲端口，扩展开机/唤醒自动探测该端口段直连并按持久 `instanceId` 自动识别或新建 Chrome 资料（首个接入资料自动激活供浏览）；彻底取消配对码仪式与手动启动连接按钮，改以每资料的「暂停写入（只读）」开关与「断开并忽略」信号控制安全与重连。

## Considered Options

- **首次写入前弹窗授权**：保留免配对自动只读镜像，仅首次写回 Chrome 前要求在桌面确认；虽比六步配对轻，但仍给零点击体验增加额外弹窗门槛，在明确支持一键「暂停写入」后没有必要保留。
- **Chrome Native Messaging**：改用轻量独立 Rust helper 通过操作系统注册表/清单通信以彻底消除本地 TCP 端口；但会引入跨平台系统注册表写入、免安装加载已解压扩展配置成本及打包复杂度，不符合当前零配置直连的简洁目标。
- **保留手动配对码作为双轨兼容**：维持两套握手与状态机使协议和设置 UI 长期背负冗余复杂度，故决定彻底废弃并移除旧配对路径。

## Consequences

- 信任边界基于同用户单机信任模型与固定扩展 Origin 隔离：本地回环监听仍严格拒绝普通网页及其他非官方 Chrome 扩展 ID 的握手，而拥有本机同用户权限的本地恶意进程原本即可直接访问磁盘书签文件，因此不再要求跨窗手工拷贝配对串。
- 实施首个协议切片（T1）时须同步更新项目治理边界与扩展规范中的配对限制条款，移除人工配对与「必须手动确认才能建连」的旧约束。
